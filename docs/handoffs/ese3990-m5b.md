## Job and outputs

The detached user service is `sailgym-m5b.service`. It runs [the supervisor](../../experiments/ese3990/m5b_study.py) using the local virtual environment with PYTHONPATH unset and XLA_FLAGS=--xla_cpu_multi_thread_eigen=false. Use `systemctl --user status sailgym-m5b --no-pager` for process state. Inspect the [phase status](../../runs/ese3990/M5b/status.json) and [per-run logs](../../runs/ese3990/M5b/main) for progress. Each run writes checkpoints and a validation curve. The status records failure details. The launcher retains incomplete directories for diagnosis and skips completed runs after checking the frozen config and budget.

After training, the service audits all stored training-run episodes, seals selected/final checkpoint identities before held-out evaluation, runs nominal/test/shift episodes and replays them. It publishes M5b_report.md, M5b_results.json and M5b_claims.json in docs/ese3990, and a completion note in the run directory. The report includes the matching stage-1 baselines. The predeclared gate requires at least three of five seeds with one or more finishes in 20 selected-checkpoint validation episodes.

To reproduce reporting after completed training, use `env -u PYTHONPATH XLA_FLAGS=--xla_cpu_multi_thread_eigen=false .venv/bin/python experiments/ese3990/m5b_study.py evaluate`. The shared service lock prevents duplicate evaluation while the main job is active. Frozen training inputs and earlier M5 rows are preserved. The quota guard reported 100% five-hour and 44% weekly allowance at setup. All remaining computation runs outside the chat.
