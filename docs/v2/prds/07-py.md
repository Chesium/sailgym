## Goal

A Gymnasium environment over `sailgym-env`, and its vectorised counterpart, such
that the Python side contains **no physical constant, no equation and no
layout** — everything is read from Rust.

This closes cross-stack §8 points 2 and 3.

## Why this shape

`cross-stack.md` §1.2 states the rule and the reason together: spaces are built
from what the Rust core reports, never typed out in Python. *"This is the same
rule F8 applies to TypeScript, and it is worth stating as such, because Python is
where that discipline usually collapses."* Section 03 already built the audit
that enforces it (F17.1); this section points it at a second package.

The second reason for the shape is negative: `sailgym-py` binds `sailgym-env`
and **not** `sailgym-wasm`. Two boundaries, different performance shapes,
different lifetimes. A binding that reused the WASM surface would inherit F8.2's
deliberate coarseness — which is right for a browser calling once per animation
frame and wrong for a training loop calling at 20 Hz × N envs.

## What this section does **not** do

- No training, no policy, no algorithm implementation. `brief.md` S4 proposes the
  environment, not a training programme.
- No PettingZoo. When multi-boat arrives, `ParallelEnv` is the right interface
  and the single-agent env stays the N = 1 specialisation of the same runtime —
  recorded here as the intended shape, built later.
- No JAX. The JAX stack reads the conformance bundle (sections 02–03); it does
  not go through this binding.
- **No f32 physical intermediates.** F9.5 and F17.5.
- No new gate step. Step 11 already delegates to `scripts/py-test.sh`, which is
  precisely why F12′ put a script there.

## The three performance non-negotiables, stated once

Each is a profile finding waiting to happen, and each is cheap now and awkward
later.

1. **Zero-copy numpy in and out.** Observations write into a caller-provided
   array, matching `step_all` with separate reward, termination, truncation and final-observation outputs and the
   `sample_wind_grid` precedent already in the repository.
2. **Release the GIL for the duration of `step_all`.** This allows other Python threads to run while Rust steps. Rayon itself can run internally even if the calling thread holds the GIL.
3. **Bounded low-level batch allocation, with a standards-compliant public adapter.** `info` dicts per step per env will
   dominate the profile. Use reusable batch buffers internally; the Gymnasium API still returns its required tuples and info dictionaries. Profile wrapper overhead separately.

These are asserted, not hoped for: task 7.5 measures all three.

### 7.2 — Spaces from the sensor layout

**Owns:** `python/sailgym/spaces.py`, `crates/sailgym-py/src/spec.rs`, `python/tests/test_spaces.py`, `python/tests/test_no_stray_constants.py`
**P-group: A**

```python
observation_space = Box(low, high, shape=(sum(s.width for s in sensors),))
action_space      = Box(-1.0, 1.0, shape=(actuation.dim,))
```

built from what Rust reports (F14.3, F14.5). **Never typed out in Python**, and
the audit from section 03 task 3.6 is extended to this package to enforce it.

`obs_digest` and its complete canonical layout record are exposed as env attributes. Training/checkpoint storage is deferred; provide an explicit compatibility-check function for later consumers. A
policy loaded against a different digest **refuses**, rather than silently
misreading its input — which is the failure that produces a plausible-looking
number that means nothing.

Acceptance: `uv run pytest python/tests/test_spaces.py` — the space shape equals
the Rust-reported layout length; the field-name list matches Rust's exactly,
order included; checking supplied incompatible observation metadata raises; the
stray-constants audit passes over `python/sailgym/`.

### 7.3 — The single environment

**Owns:** `python/sailgym/env.py`, `crates/sailgym-py/src/env.rs`, `python/tests/test_env.py`
**P-group: A**

Gymnasium's `Env`. `reset(seed=k)` maps **straight** onto the Rust `u64`
(F17.3), and `np_random` touches nothing in the simulation — not wind, not
sensor noise, not scenario sampling. A randomised scenario derives from the same
`u64` through `STREAM_SCENARIO`.

`Outcome` is read from Rust and mapped to `(terminated, truncated)`. **No
`TimeLimit` wrapper** (F17.4): the vectorised path cannot use Python wrappers,
so a wrapper-supplied truncation would make the single-env and vector paths
disagree about episode boundaries — silently, in the returns.

Acceptance: `uv run pytest python/tests/test_env.py` —
`gymnasium.utils.env_checker.check_env` passes; `reset(seed=k)` twice gives
identical observations; two different `np_random` draws with the same `k` give
identical trajectories (this is the assertion that catches a leaked RNG);
`terminated` and `truncated` are never both true.

### 7.4 — The vector environment, and the Python half of point 3

**Owns:** `python/sailgym/vector.py`, `crates/sailgym-py/src/vector.rs`,
`python/tests/test_autoreset.py`
**P-group: B**

`VectorEnv` over `sailgym-env`'s `VecEnv`. Caller-provided buffers, GIL released
around `step_all`.

Section 06 pinned the autoreset convention in Rust and asserted the returns
identity there. This task asserts the **same** identity through the binding, on
the same fixed action sequence and the same seed, and additionally asserts that
the single-env and vector paths agree about episode boundaries step for step.
Two implementations of a convention is how a convention stops being one.

Acceptance: `uv run pytest python/tests/test_autoreset.py` — discounted returns
computed both ways agree to the bound section 06 established; single-env and
`VectorEnv` with N = 1 produce identical `(obs, reward, terminated, truncated)`
sequences; N = 8 with identical seeds produces eight identical rows.

### 7.5 — The performance assertions

**Owns:** `python/tests/test_performance.py`
**P-group: B**

The three non-negotiables, measured:

- **Zero-copy**: the observation array's `__array_interface__` data pointer is
  unchanged across `step_all` calls, and writing into the caller's buffer is
  observable from Python.
- **GIL released**: `step_all` on a large N overlaps with a Python thread doing
  measurable work — asserted as a ratio against the serialised baseline, with a
  stated numeric bound, and skipped with a message (never silently) on a
  single-core host.
- **Bounded memory**: measure retained memory across 1 000 steps and peak temporary allocation separately. Stable retained memory does not prove zero allocations. Report low-level buffers separately from required Gymnasium tuple/dict creation.

These are numeric assertions, per F13.4. A comment saying "we release the GIL"
is not one.

Acceptance: all three pass, with their bounds stated in the test, and the
measured values recorded in the handoff.
